STARTUPNEST - COMPLETE PROJECT FLOW DOCUMENTATION
===================================================

This document serves as the master technical and functional description of the StartupNest project — a full-stack application connecting Entrepreneurs and Mentors through an organized digital platform. It covers backend architecture, frontend flow, API endpoints, team member responsibilities, and implementation logic. The goal is to offer a transparent, SonarQube-friendly, and well-documented explanation of every component for maintainability, onboarding, and quality assurance purposes.

---------------------------------------------------------------------
PROJECT OVERVIEW
---------------------------------------------------------------------
StartupNest addresses the gap between startup founders seeking mentorship/funding and experienced professionals willing to invest or guide in specific sectors. The system is built using Node.js, Express, MongoDB on the backend and React, Redux Toolkit, and React Query on the frontend. Each component has been written modularly and tested to maintain high quality metrics under SonarQube inspection.

Functional Goals:
1. Allow mentors to publish startup profiles that specify their investment domain, funding capacity, and expectations.
2. Allow entrepreneurs to discover these opportunities, apply, and submit pitch decks securely.
3. Provide a structured review system where mentors can shortlist or reject startup submissions.
4. Maintain transparency between mentor-entrepreneur interactions and ensure security and scalability.

---------------------------------------------------------------------
PROBLEM STATEMENT
---------------------------------------------------------------------
Entrepreneurs often struggle to find tailored mentorship or investment opportunities due to fragmented communication channels. Existing solutions lack filtering, personalization, and secure submission handling. StartupNest aims to centralize this process by:
- Providing a searchable catalog of mentor startup profiles.
- Allowing PDF pitch deck uploads tied to a specific mentor profile.
- Offering a two-way feedback and review system.
- Ensuring data protection and maintaining code quality standards.

---------------------------------------------------------------------
TEAM AND RESPONSIBILITIES
---------------------------------------------------------------------
The StartupNest team consists of five members, each responsible for specific modules across both backend and frontend:

1. Karthik – Startup Profile Controller, Button Component, Auth Utils
2. Venu – Startup Submission Controller, Signup Component, My Submissions, Toast Integration
3. Vedant – User Controller, Mentor Navbar, User APIs, SelectField Component
4. Rajitha – Startup Profile Routes, Submission APIs, AuthExpired Modal, ErrorPage, PrivateRoute
5. Pawan – Models (StartupSubmission, User), ReusableModal, EntrepreneurNavbar, Index Setup, Redux Slice, App Integration

---------------------------------------------------------------------
ARCHITECTURE OVERVIEW
---------------------------------------------------------------------
The system follows an MVC (Model-View-Controller) structure on the backend and a component-based design on the frontend. It integrates with MongoDB for persistent data storage. JSON Web Tokens (JWT) secure private routes, while role-based navigation ensures different flows for mentors and entrepreneurs.

Backend Stack:
- Node.js
- Express.js
- MongoDB (via Mongoose)
- JWT for Authentication
- bcrypt for Password Hashing

Frontend Stack:
- React (Create React App)
- Redux Toolkit for global state
- React Query for server state management
- axios for API communication
- React Router for routing

Quality Stack:
- ESLint + Prettier
- Jest for testing
- SonarQube for code quality metrics

---------------------------------------------------------------------
DATA FLOW (SIMPLIFIED)
---------------------------------------------------------------------
1. User registers or logs in.
2. JWT token is issued and stored in localStorage.
3. Mentors create startup profiles via the dashboard.
4. Entrepreneurs browse available profiles.
5. Entrepreneurs submit ideas (with pitch decks) referencing a selected mentor profile.
6. Mentors review submissions and update statuses (Shortlisted/Rejected).
7. Entrepreneurs can track submission statuses under "My Submissions".
8. Application uses pagination, search, and sorting for scalability.

---------------------------------------------------------------------
DATABASE SCHEMAS
---------------------------------------------------------------------
(1) USER MODEL - (Owned by Pawan)
Fields:
- userName: String
- email: String
- password: String
- mobile: String
- role: String (Entrepreneur | Mentor)

(2) STARTUP PROFILE MODEL - (Owned by Rajitha)
Fields:
- mentorId: ObjectId (User)
- category: String
- description: String
- fundingLimit: Number
- avgEquityExpectation: Number
- targetIndustry: String
- preferredStage: String
- createdAt: Date

(3) STARTUP SUBMISSION MODEL - (Owned by Pawan)
Fields:
- userId: ObjectId (User)
- startupProfileId: ObjectId (StartupProfile)
- submissionDate: Date
- marketPotential: Number
- launchYear: Date
- expectedFunding: Number
- pitchDeckFile: String (Base64 or file path)
- status: Number (1: Submitted, 2: Shortlisted, 3: Rejected)
- address: String

---------------------------------------------------------------------
BACKEND ROUTES AND ENDPOINTS
---------------------------------------------------------------------
[USER ROUTES - Vedant]
POST /user/signup
POST /user/login

[STARTUP PROFILE ROUTES - Rajitha]
POST /startupProfile/addStartupProfile
GET /startupProfile/getAllStartupProfiles
GET /startupProfile/getStartupProfileById/:id
PUT /startupProfile/updateStartupProfile/:id
DELETE /startupProfile/deleteStartupProfile/:id

[STARTUP SUBMISSION ROUTES - Venu]
POST /startupSubmission/addStartupSubmission
GET /startupSubmission/getAllStartupSubmissions
GET /startupSubmission/getSubmissionsByUserId/:id
PUT /startupSubmission/updateStartupSubmission/:id
DELETE /startupSubmission/deleteStartupSubmission/:id
GET /startupSubmission/getSubmissionFile/:id

Each route is protected by JWT middleware except login/signup.

---------------------------------------------------------------------
FRONTEND STRUCTURE AND FLOW
---------------------------------------------------------------------
The React application is modular, with dedicated folders for each role (Mentor, Entrepreneur, Common). React Router defines private routes that depend on authentication status and user role.

Example navigation:
- Mentor → /mentor/home → can access Add, Edit, and View profiles.
- Entrepreneur → /entrepreneur/home → can view opportunities and submit ideas.

Each page integrates reusable components and maintains minimal logic inside components by delegating tasks to helper APIs.
